# MCP-сервер Крометры

Через этот сервер ИИ-клиент (Claude Code и другие клиенты MCP) управляет живым редактором Крометры: читает модель, выполняет операции, получает снимок вьюпорта с подписанными id рёбер и граней.

Геометрию считает браузер, поэтому команды всегда исполняет страница редактора через канал управления `window.cadControl`. Сервер не знает ни одной операции моделирования: список операций и их параметры он получает от редактора (`capabilities`) и передаёт вызовы как есть. Новая операция в канале становится доступна клиенту без правок сервера.

Удалённый режим - вкладка пользователя подключается к серверу на сайте по WebSocket:

```
ИИ-клиент  <- HTTP /mcp (Bearer krm_...) ->  web/mcp/remote-server.mjs  <- WebSocket /mcp/ws ->  вкладка /editor/<id>  ->  window.cadControl
                                                    |
                                                    +-- backend /api (вход по ключу, проекты, проверка токена вкладки)
```

Локальный режим - сервер сам держит страницу редактора в Chromium:

```
ИИ-клиент  <- stdio JSON-RPC ->  web/mcp/server.mjs  <- Playwright ->  страница /editor/<id>  ->  window.cadControl
                                        |
                                        +-- /api/auth/token, /api/projects/  (вход и проекты, без браузера)
```

## Подключение к Claude Code

Есть два режима, инструменты у них одинаковые.

- **Удалённый (рекомендуется).** Сервер работает на сайте Крометры по адресу `https://<сайт>/mcp`, ставить ничего не нужно. Команды ИИ выполняются в открытой у пользователя вкладке редактора: модель меняется у него на глазах, а во вьюпорте горит значок «ИИ-агент управляет редактором».
- **Локальный.** Сервер ставится на компьютер и сам открывает редактор в фоновом Chromium через Playwright. Вкладку держать не нужно, но нужны git, Node 22+ и Chromium.

### Удалённый сервер

1. На странице «Аккаунт» (`/account`) создай ключ доступа `krm_...`. Ключ показывается один раз; рядом страница показывает готовую команду и кнопку «Скопировать инструкцию для агента» - готовый текст для ИИ с командой и проверкой.
2. Подключи сервер для всех проектов Claude Code:

   ```bash
   claude mcp add krometra -s user --transport http https://krometra.ru/mcp \
     --header 'Authorization: Bearer krm_...'
   ```

   `--header` стоит последним: он принимает несколько значений и иначе забрал бы имя сервера и адрес.
3. Открой проект в браузере, войдя тем же пользователем, что и владелец ключа. Вкладка редактора сама подключается к серверу, когда ядро готово. Если вкладка закрыта, `cad_open_project` ждёт её до минуты и затем отвечает ссылкой, которую нужно открыть.
4. Проверь: `claude mcp list` показывает `krometra` со статусом `Connected`, затем попроси ассистента показать список проектов.

Файлы в удалённом режиме идут через сервер, а не через диск: `cad_export` отвечает ссылкой на 15 минут (качается `curl` без ключа: ссылка случайная и одноразово выданная), `cad_import` выдаёт одноразовую ссылку загрузки, в которую файл отправляется `curl -X PUT --data-binary @файл.step`, и вторым вызовом импортирует загруженное.

### Локальный сервер

```bash
git clone https://github.com/nia-sempai/krometra.git ~/krometra
cd ~/krometra/web && npm install
npx playwright install chromium
claude mcp add krometra -s user \
  -e CAD_STUDIO_URL=https://krometra.ru \
  -e CAD_STUDIO_API_KEY=krm_... \
  -- "$(command -v node)" "$HOME/krometra/web/mcp/server.mjs"
```

- Если скачать Chromium нельзя, задай `CAD_STUDIO_BROWSER_CHANNEL=chrome`, и сервер запустит установленный Google Chrome.
- `-s user` подключает сервер во всех проектах Claude Code, а не только в текущем каталоге.
- `$(command -v node)` подставляет полный путь к node: Claude Code запускает сервер без профиля shell, и node из nvm в его PATH может не оказаться.
- Если репозиторий склонирован в другое место, замени путь к `web/mcp/server.mjs` на свой (абсолютный).
- Проверка без клиента: `printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | node web/mcp/server.mjs`.
- Смотреть, что рисует локальный сервер, можно в своём браузере: `cad_open_project` возвращает `watchUrl` - ссылку на тот же проект в режиме наблюдения (`/editor/<id>?watch=1`). В нём нет правок, горячих клавиш и автосохранения, поэтому вкладка не мешает ИИ, а модель подтягивается сама раз в полторы секунды без сброса камеры.

### Отзыв ключа

Удали ключ на странице «Аккаунт»: доступ пропадает сразу, следующий вызов инструмента вернёт ошибку входа. Сервер из Claude Code убирается командой `claude mcp remove krometra -s user`. Чтобы сменить ключ, создай новый, удали сервер и подключи его заново с новым ключом.

### Локальная разработка

Для локального стека (`make up` и `cd web && npm run dev`) адрес - `http://localhost:5173`, ключ создаётся так же, на `http://localhost:5173/account`. Проверка адреса: `curl localhost:5173/api/health` должен вернуть `"app":"Крометра"`. Порт 5173 бывает занят другим проектом, сервер это проверяет сам и чужому приложению ключ не отправит.

Удалённый сервер в dev: `make up` поднимает и сервис `mcp` (порт 8787), vite проксирует на него `/mcp` вместе с WebSocket. Вкладка подключается к ретранслятору, только если фронт собран с `VITE_MCP_RELAY=1` (в образе `web` это по умолчанию): `VITE_MCP_RELAY=1 npm run dev`. Без стека сервер запускается и так: `BACKEND_URL=http://localhost:8000 PUBLIC_URL=http://localhost:5173 node web/mcp/remote-server.mjs`.

Запасной вариант для локального сервера - вход почтой и паролем через `CAD_STUDIO_EMAIL` и `CAD_STUDIO_PASSWORD` вместо `CAD_STUDIO_API_KEY`. Если задан ключ, почта и пароль не используются. Для ИИ лучше завести отдельного пользователя: e2e-сетап (`web/e2e/auth.setup.ts`) удаляет все проекты своего пользователя.

После правки кода сервера нужен перезапуск: `/mcp` -> krometra -> Reconnect (удалённый - пересборка сервиса `mcp`).

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `CAD_STUDIO_URL` | `http://localhost:5173` | Базовый адрес приложения (сайт или фронт с прокси `/api`). |
| `CAD_STUDIO_API_KEY` | нет | Ключ доступа `krm_...` со страницы «Аккаунт». Основной способ входа. |
| `CAD_STUDIO_EMAIL` | нет | Запасной вход: email пользователя. Используется, только если ключ не задан. |
| `CAD_STUDIO_PASSWORD` | нет | Запасной вход: пароль пользователя. Используется, только если ключ не задан. |
| `CAD_STUDIO_HEADLESS` | `1` | `0`, `false`, `no` или `off` открывают видимое окно браузера: можно смотреть, что делает ИИ. |
| `CAD_STUDIO_BROWSER_CHANNEL` | `chromium` | Какой браузер запускать: `chromium` (Chromium от Playwright) или `chrome` (установленный Google Chrome). |
| `CAD_STUDIO_READY_TIMEOUT_MS` | `60000` | Сколько ждать готовности редактора при открытии проекта. |
| `CAD_STUDIO_REQUEST_TIMEOUT_MS` | `120000` | Сколько ждать ответа канала на одну операцию. |

Удалённый сервер (сервис `mcp`) настраивается своими переменными:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MCP_PORT` | `8787` | Порт HTTP и WebSocket. |
| `BACKEND_URL` | `http://localhost:8000` | Backend для входа по ключу, проектов и проверки токена вкладки (в compose - `http://app:8000`). |
| `PUBLIC_URL` | `http://localhost:5173` | Публичный адрес сайта: из него строятся ссылки на редактор и на файлы экспорта. В проде берётся из `.env`. |
| `MCP_OPEN_TIMEOUT_MS` | `60000` | Сколько `cad_open_project` ждёт, пока пользователь откроет вкладку проекта. |
| `MCP_REQUEST_TIMEOUT_MS` | `120000` | Сколько ждать ответа вкладки на одну операцию. |

Без ключа (и без пары email и пароль) локальный сервер стартует, а инструменты отвечают ошибкой: какой переменной не хватает и на какой странице создать ключ. Ключ, пароль и токены не попадают ни в ответы инструментов, ни в stderr: известные секреты и всё похожее на JWT маскируется на выходе.

## Инструменты

| Инструмент | Параметры | Что делает |
|---|---|---|
| `cad_list_projects` | нет | Список проектов пользователя. Браузер не запускает. |
| `cad_create_project` | `name`, `description?` | Создаёт пустой проект, возвращает id. |
| `cad_open_project` | `project_id` (id или ссылка `/editor/<id>`) | Локально открывает проект в браузере сервера и ждёт `cadControl.ready`, отдаёт `watchUrl` для наблюдения. Удалённо привязывается к открытой вкладке проекта (или ждёт её) и отдаёт ссылку на проект. |
| `cad_capabilities` | нет | Операции канала: имя, описание, мутирует ли модель, параметры. Единственный источник правды об операциях. |
| `cad_state` | нет | Состояние редактора: режим, ядро, документ, тела, эскизы, timeline, busy. |
| `cad_request` | `op`, `params?` | Передаёт `{ op, params }` в `cadControl.request` и возвращает ответ как есть. |
| `cad_snapshot` | `labels?` (`none`, `edges`, `faces`), `body_id?`, `label_text?` (`id`, `number`), `body_ids?` | Снимок вьюпорта как изображение; с `labels` на нём подписаны рёбра или грани тела, рядом текстовая легенда. С `body_ids` на снимке только эти тела (остальные временно скрыты, документ не меняется). |
| `cad_section` | `plane` (`XY`, `XZ`, `YZ`), `offset?`, `body_ids?`, `points?` | Сечение плоскостью: картинка контуров (тела разными цветами) и их замкнутость, площадь, длина и габарит в координатах плоскости. |
| `cad_export` | локально `format`, `path`, `body_ids?`, `overwrite?`; удалённо `format`, `body_ids?`; для STL и 3MF `quality?`, `tolerance?`, `angle_deg?` | Локально пишет STL, STEP или 3MF на диск и возвращает путь; удалённо отдаёт ссылку на файл на 15 минут и готовую команду `curl`. |
| `cad_import` | локально `path`; удалённо `upload_id?` | Импорт STEP: каждое твёрдое тело файла - отдельное тело документа. Удалённо в два шага: ссылка загрузки, затем импорт загруженного. |

Ошибка инструмента возвращается результатом с `isError: true`, сервер при этом продолжает работать. Ответ канала с `ok: false` тоже помечается `isError`, а вторым текстовым блоком идёт подсказка по коду ошибки (`busy` - повторить через 1-2 секунды, `unknown_op` и `invalid_params` - свериться с `cad_capabilities`, и так далее).

## Порядок работы

1. `cad_list_projects` или `cad_create_project` - получить id проекта.
2. `cad_open_project` - без него остальные инструменты отвечают ошибкой.
3. `cad_capabilities` - узнать операции и параметры. Имена операций не угадываются.
4. `cad_state`, `cad_snapshot` - прочитать модель.
5. `cad_request` - выполнить операцию. Координаты и размеры в миллиметрах.
6. `cad_state` или `cad_snapshot` - убедиться в результате.
7. `cad_export` - сохранить STL или STEP.

Отмена - `history.undo`: откатывает ровно последнюю запись истории (операцию, создание или правку эскиза, удаление тела или записи) и сообщает в `undone`, что именно откатилось. Тела, скрытые операцией, снова видны; `history.redo` возвращает те же id тел и записей. Если то, что создала операция, изменено после неё, отмена честно отказывает `operation_failed` и модель не трогает.

Пример, проверенный на живом редакторе (имена операций взяты из `capabilities` и могут измениться вместе с каналом):

```
cad_create_project { "name": "Кронштейн" }                       -> { "id": "64d8..." }
cad_open_project   { "project_id": "64d8..." }                   -> { "channelVersion": 1, ... }
cad_capabilities                                                 -> { "version": 1, "ops": [...] }
cad_request { "op": "sketch.create", "params": { "plane": "XY", "entities": [
  { "type": "rectangle", "corner1": { "x": -20, "y": -15 }, "corner2": { "x": 20, "y": 15 } } ] } }
                                                                 -> { "ok": true, "result": { "sketchId": "sketch-..." } }
cad_request { "op": "extrude", "params": { "sketchId": "sketch-...", "distance": 20 } }
                                                                 -> { "ok": true, "result": { "feature": { "bodyId": "body-..." } } }
cad_snapshot { "labels": "edges" }                               -> картинка + легенда с id рёбер
cad_request { "op": "fillet", "params": { "bodyId": "body-...", "edgeIds": ["e-2mqi2sfajd"], "radius": 4 } }
cad_state                                                        -> новое тело в bodies, запись в timeline
```

## Приёмы моделирования

- **Тело на высоте.** Эскиз ставится на смещённую базовую плоскость: `sketch.create { plane: "XY", offset: 4, entities }`, затем `extrude` - тело начинается на Z = 4 без грани-опоры и обратного выреза. Так же работают `XZ` (смещение по Y) и `YZ` (по X).
- **Эскиз на торце.** `extrude` с `extent = distance` возвращает `capFaceIds` (дальний торец) и `baseFaceIds` (грань в плоскости эскиза): на них сразу ставят `sketch.create { bodyId, faceId }`. Любую другую грань находит `face.find { bodyId, normal?, point? }`, не читая всю топологию; `topology` сокращается фильтрами `include`, `planar`, `normal`.
- **Контур грани в эскизе.** Эскиз на грани получает её кромки сущностями построения: прямая - `line`, круглая - `circle`, дуга - `arc`.
- **Массивы.** В `entities` эскиза можно передать `{ type: "linear_pattern", entities, count, step, count2?, step2? }` или `{ type: "circular_pattern", entities, count, center, angle? }`: гребёнку 2×14 отверстий с шагом 2,54 мм задаёт один элемент.
- **Цепочка тел.** join, cut, скругление, фаска, резьба, булева операция и перемещение поглощают исходное тело и дают результату новый id. `state.bodies` по умолчанию показывает только живые тела; поглощённые - с `allBodies: true`, у них `consumedBy` (запись истории) и `replacedBy` (тело-результат).
- **Перемещение и копии.** `body.transform { bodyId, translate?, rotate?: { axis, angle, origin? }, copy? }` - запись истории `transform`; с `copy: true` исходное тело остаётся. Id граней переносятся на результат.
- **Зеркало.** `body.mirror { bodyId, plane?: XY | XZ | YZ, offset?, faceId?, merge? }` - запись истории `mirror`: отражение относительно базовой плоскости (со смещением вдоль её нормали) или плоской грани самого тела. Без `merge` результат - новое тело, исходное остаётся; с `merge: true` отражение объединяется с исходным в одно тело. Плоскость и смещение потом правятся из дерева с пересборкой.
- **Сдвиг грани (Press-Pull).** `pressPull { bodyId, faceIds, distance, newBody? }` - запись истории `press_pull`: плоские и цилиндрические грани уходят по нормали на `distance` со знаком (плюс наружу, минус внутрь; зазор под посадку `-0.07`, отверстие шире на 1 - `-1` по его стенке). Сдвинутая грань сохраняет id. С `newBody: true` грань выдавливается в новое тело, исходное остаётся. Смещение правится из дерева с пересборкой.
- **Несколько тел за одну операцию.** `boolean { operation, targetBodyId, toolBodyIds: [...], keepTools? }` - одна запись истории на цель и любое число инструментов; `keepTools: true` оставляет инструменты видимыми телами. `extrude { operation: "cut", targetBodyIds: [...] }` режет все перечисленные тела одним вырезом (без списка и без `targetBodyId` - все видимые); тела, которых инструмент не касается, пропускаются.
- **Массив.** `body.pattern { bodyId, type: "linear" | "circular", axis, count, spacing?, angle?, axis2?, count2?, spacing2?, separate? }` - запись истории `pattern`; ось - X/Y/Z, прямое ребро, грань или произвольная прямая. По умолчанию копии объединяются с исходным телом; так размножают тело-инструмент и вычитают его одной булевой операцией (четыре ножки).
- **Уборка.** `body.delete` удаляет тело вместе с историей, из которой оно выросло, `timeline.delete` - одну запись (зависимые пересобираются от её исходного тела, а те, что без неё не строятся, остаются в истории с ошибкой), `timeline.suppress` - выключает операцию, не удаляя её, `timeline.rollback` - переносит маркер отката (новые операции встают в точку маркера), `timeline.deleteAfterMarker` - удаляет всё после маркера, `sketch.delete` - неиспользованный эскиз. Всё отменяется `history.undo`. Видимость, имя и цвет тела - `body.setVisible`, `body.rename`, `body.setColor`. Эскиз, по которому построена операция, во вьюпорте скрыт по умолчанию; показать или скрыть контур эскиза - `sketch.setVisible`.
- **Проверка внутренностей.** `cad_section` (или op `section`) показывает контуры сечения - зазоры, толщины, отверстия; `mesh.stats` с `zLevels` - быстрые высоты.
- **Знак расстояния.** В `params` записи `extrude` поле `distance` хранится со знаком вдоль нормали эскиза. Повторить операцию: `distance = |distance|`, `reversed = (operation = cut ? distance > 0 : distance < 0)`.
- **Разрезанная грань.** Если операция разрезала грань на части, одна часть сохраняет прежний id, остальные получают его с суффиксом `~1`, `~2`.
- **Сбой связи.** `save_failed` значит: геометрия построена, но сервер не сохранил её даже после повторов (обрыв связи, 502-504). Модель не изменилась - сверь `cad_state` и повтори ту же операцию через 10-20 секунд. `operation_failed` - отказ по существу, повтор с теми же параметрами не поможет.

## Снимок с подписями

`cad_snapshot { "labels": "edges" }` берёт `topology` тела, проецирует середины рёбер через `viewport.project`, снимает вьюпорт через `viewport.capture` и рисует подписи поверх снимка операцией `image.drawLabels` в самой вкладке - поэтому инструмент одинаково работает локально и удалённо. Вторым блоком идёт легенда, по одному объекту на строку:

```
{"bodyId":"body-0037f21469a2","kind":"edges","units":"mm","image":{"width":876,"height":674},"labeled":12,"offscreen":0,"items":[
{"id":"e-2mqi2sfajd","start":[-20,-15,20],"end":[20,-15,20],"at":[384,315]},
...
]}
```

- `id` - точный идентификатор для операций; `start`, `end` - концы ребра в мм; у грани `point` (точка на грани) и `normal` (у плоских); `at` - пиксель метки на снимке.
- `label_text: "number"` ставит на снимок номера, а соответствие номера и id отдаёт в легенде (`label`). Пригодится, когда подписи сливаются.
- `body_id` можно не указывать, если видимое тело одно.
- Подписываются все объекты в кадре, включая заслонённые телом: канал не сообщает видимость. Выбирать объект надёжнее по координатам из легенды, чем по картинке.
- Объекты вне кадра не подписываются и считаются в `offscreen`. Подписей не больше 120, остаток указан в `notes`: приблизь камеру.
- Проекция снимается до и после съёмки. Если камера сдвинулась, снимок повторяется; если она так и не остановилась, в `notes` будет предупреждение.
- Ракурс меняется операцией канала: `cad_request { "op": "camera.set", "params": { "position": [90, -110, 80], "target": [0, 0, 10] } }`.

## Экспорт в файл

Локальный `cad_export` вызывает операцию канала `export`, пишет полученные байты на диск и отвечает текстом:

```
cad_export { "format": "stl", "path": "/Users/me/print/" }
-> {"path":"/Users/me/print/Кронштейн.stl","bytes":684,"mime":"model/stl","filename":"Кронштейн.stl"}
```

- Без `body_ids` в файл идут все видимые тела, как у кнопки «Экспорт». С `body_ids` - ровно названные тела. Отдельный STL на каждое тело получают отдельными вызовами с одним id в `body_ids`.
- Точность сетки STL и 3MF: `quality` (`draft` - 0.1 мм и 30°, `normal` по умолчанию - 0.01 мм и ~28.6°, `high` - 0.002 мм и 6°) или свои `tolerance` (мм) и `angle_deg` поверх пресета. 3MF - zip с `3D/3dmodel.model` в миллиметрах, по объекту на тело.
- `path` - абсолютный путь (допустим `~/`). Путь с расширением формата (`.stl`, `.3mf`, `.step`, `.stp`) - это файл. Существующий каталог, путь с завершающим слэшем и путь без расширения - каталог: он создаётся при необходимости, имя файла даёт редактор.
- Существующий файл не перезаписывается без `overwrite: true`. Для пути файла отказ приходит до обращения к редактору.
- Расширение, не подходящее формату, отклоняется: STL не окажется в файле `.step`.
- От имени файла из редактора берётся только последняя часть пути, так что запись не выйдет за пределы указанного каталога.

Через `cad_request` файл получить нельзя: base64 в ответ не передаётся, вместо него стоит заглушка с подсказкой вызвать `cad_export`. Исключение - изображения (`mime` начинается с `image/`), они уходят отдельным image-блоком.

## Вход и сессия

Вход идёт по API, без кликов по форме: `POST /api/auth/token` с `grant_type=api_key` и полем `api_key` (запасной вариант - password grant). Сессия, полученная по ключу, привязана к нему: удаление ключа сразу обрывает и access token, и refresh-сессию браузера. Сервер сам никогда не обновляет токен через refresh: когда access token протухает, он входит заново тем же ключом. Браузер получает refresh-cookie от входа, сделанного специально для него, и дальше ротирует её сам. Так одна и та же refresh-кука не предъявляется дважды, и защита от replay на backend не убивает сессию. Роуты API вызываются с завершающим слэшем (`/api/projects/`), редирект мимо vite-прокси считается ошибкой.

## Тесты

```bash
cd web && npm run test:mcp
```

Тестам не нужен поднятый стек: они запускают локальный http-сервер со страницей-заглушкой, которая реализует `window.cadControl` и нужные ручки API, поднимают MCP-сервер дочерним процессом и гоняют JSON-RPC сценарии в headless Chromium. `remote.test.mjs` поднимает удалённый сервер в процессе теста, подключает к нему поддельную вкладку по WebSocket и проверяет вход по ключу, сессии, ретрансляцию команд, ссылки экспорта и загрузки. `export.test.mjs` пишет файлы во временный каталог и удаляет его. `labels.test.mjs`, `core.test.mjs` и `maixcam.test.mjs` проверяют чистую логику без браузера.

e2e на живом стеке (`make up`, `cd web && npm run dev`, `/api/health` отвечает `"app":"Крометра"`):

```bash
cd web && npm run e2e:mcp
```

`e2e/mcp-maixcam.spec.ts` запускает `server.mjs` дочерним процессом с `CAD_STUDIO_URL=E2E_BASE_URL` (по умолчанию `http://localhost:5173`) и входом e2e-пользователя (`E2E_USER_EMAIL`, `E2E_USER_PASSWORD`), рисует уменьшенную плату MaixCAM (контур из `line` и `arc` с отверстиями, цепочка join, камера на стойках обратным cut, эскиз на грани), экспортирует STEP и STL во временный каталог и снимает вьюпорт. Созданные проекты удаляются в конце, адрес `krometra.ru` тест отклоняет. Регрессии из ревью живого рисования помечены `test.fail`: после фикса бага такой тест начнёт проходить, Playwright покажет это падением, и `test.fail` меняется на `test`.

## Протокол вкладки и деплой

Вкладка редактора (не в режиме наблюдения) после готовности канала открывает `wss://<сайт>/mcp/ws` и шлёт `{ type: "hello", token, projectId, channelVersion }`, где `token` - её access token. Сервер проверяет токен через `/api/auth/me` и отвечает `welcome` или `rejected`. Дальше сервер шлёт `{ type: "request", id, request: { op, params } }`, вкладка отвечает `{ type: "reply", id, reply }` ответом `window.cadControl.request`, а `{ type: "session", attached }` включает и гасит значок «ИИ-агент управляет редактором». Команды сессии MCP уходят только во вкладку того же пользователя, что и владелец ключа, и только с тем проектом, который открыт через `cad_open_project`; при нескольких вкладках проекта - в последнюю подключившуюся. Вкладка переподключается сама с паузой до 30 секунд.

В проде сервис `mcp` описан в `docker-compose.prod.yml`, nginx проксирует на него `/mcp` вместе с WebSocket (`web/nginx-app.conf`), адрес для ссылок берётся из `PUBLIC_URL` в `.env` (его дописывает `scripts/deploy.sh`). Фронт собирается с `VITE_MCP_RELAY=1`.

## Ограничения

- Одновременно открыт один проект в одной странице (локально) или в одной сессии MCP (удалённо). `cad_open_project` с другим id переключает редактор.
- Удалённому режиму нужна открытая вкладка проекта: если её закрыть, вызовы отвечают ошибкой со ссылкой, которую нужно открыть снова.
- Если страница редактора перезагрузилась после открытия (например, vite пересобрал модули), вызовы вернут ошибку: открой проект заново через `cad_open_project`. Перезагрузку во время открытия сервер переживает сам.
- Большой ответ канала (например `topology` тела с резьбой) возвращается целиком, клиент может его обрезать.
- `cad_request` не передаёт base64 в текст ответа: изображение уходит отдельным image-блоком, остальные бинарные данные заменяются заглушкой. Для снимков есть `cad_snapshot`, для файлов - `cad_export`.
- Файл экспорта целиком проходит через память сервера и браузера: очень большие модели упираются в `CAD_STUDIO_REQUEST_TIMEOUT_MS`.
