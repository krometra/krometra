# AGENTS.md

Лучшие практики разработки Крометры — браузерной CAD-системы с геометрическим ядром OCCT/WASM в браузере. Документ описывает принципы, которым следует придерживаться при добавлении функциональности.

> Контекст продукта и архитектура — в [`.docs/gdd.md`](./.docs/gdd.md). Конвенции кода и команды — в [`CLAUDE.md`](./CLAUDE.md).

## Документация

- [`.docs/gdd.md`](./.docs/gdd.md) — Product Design Document: видение, scope MVP, архитектура, план развития. Источник истины по продукту.
- [`.docs/ROADMAP.md`](./.docs/ROADMAP.md) — порядок фаз развития + **инженерная аналитика качества**: приоритизированный план работ по техдолгу и тестам. Выбираешь, что делать дальше, — сверься с ним.
- [`CLAUDE.md`](./CLAUDE.md) — конвенции кода и команды репозитория.
- [`README.md`](./README.md) — обзор проекта и быстрый старт.

## Процесс работы

- Работаем в `master` напрямую. Ветка заводится только под крупное изменение, которое живёт дольше одной сессии, или когда её просит пользователь.
- Что делать дальше — выбирай по `.docs/ROADMAP.md`. Крупное изменение можно провести через OpenSpec (`/opsx:explore` → `/opsx:propose` → `/opsx:apply` → `/opsx:archive`), но для обычной работы это не обязательно.
- Не оставляй сборку и тесты красными: `npm run build`, `npm run lint`, `pytest` и e2e должны быть зелёными до коммита.
- **Спеки инкрементов — только в `openspec/changes/<имя>/`.** Не создавай `increment-spec.md` (или подобные временные спеки) в корне репо: история уже накопила 17 коммитов «добавил спеку → удалил спеку».
- **Миграции:** не правь существующие — добавляй новую.
- **Файлы, которые правит почти любое изменение** — держи правки минимальными:
  - backend: `app/main.py` (регистрация роутов), `app/api/deps.py`, `app/models/__init__.py`, `requirements.txt`, миграции `alembic/versions/`;
  - frontend: `web/src/router/index.ts`, `web/src/types/api.ts`, `package.json`;
  - **`web/src/views/EditorView.vue` и `ViewportContainer.vue`** — самые горячие файлы репо. Оба декомпозированы до тонких оркестраторов (EditorView — июль 2026, логика в `composables/editor/`, разметка в `components/editor/`, карта — `web/src/components/editor/README.md`; ViewportContainer — 19.08.2026, домены в `composables/viewport/`). Новую логику в них **не добавляй** — только подключение composable + тег компонента (см. секцию «Редактор»).

## Принципы

- **GDD — источник истины.** Любая фича сверяется со scope MVP (`.docs/gdd.md`, раздел 3). Не реализуй то, что явно отнесено к v1/v2, без согласования.
- **Многопользовательская архитектура с первого дня.** Любые данные принадлежат пользователю. Изоляция по `owner_id` обязательна на уровне запроса, а не только UI.
- **Геометрия — в браузере.** B-rep считает OCCT/WASM в `web/src/workers/browser-geometry.worker.ts`; сервер хранит документ, права и opaque-файлы (STEP + меш), проверяет контракт меша и геометрию не интерпретирует. Серверного fallback нет.
- **Минимум комментариев.** Самодокументирующийся код: понятные имена, маленькие функции. Комментарий — только для непереводимого в код «почему».
- **Маленькие вертикальные срезы.** Фича доходит до работающего состояния через все слои (модель → сервис → API → composable → UI), а не «сначала весь backend, потом весь frontend».

## Качество кода (весь репозиторий)

Анти-паттерны, найденные при декомпозиции EditorView (июль 2026, 3358 → 580 строк), не уникальны для редактора — те же нашлись в `ViewportContainer.vue`, `SketcherContainer.vue` и `geometry_service.py` (все три разобраны, август 2026). Применяй эти правила везде, backend включительно:

- **Крупный файл — оркестратор, и он не растёт.** View-компонент, роут, крупный модуль — это раскладка и связывание; логика уезжает в composables/сервисы, разметка — в дочерние компоненты. Если твоё изменение добавляет в такой файл больше пары десятков строк логики — ей место в отдельном модуле. Потолок гейтит линтер (`max-lines: 600`); монолитов не осталось, ближайшие к порогу — `PropertiesPanel.vue` (586), `DashboardView.vue` (564).
- **Одна функция — одно действие.** Не совмещай два поведения через опциональные аргументы: старый `selectFeature(id?, action?)` делал и выделение фичи, и запуск инструментов — из-за этого баг «„Вращать“ запускает выдавливание» было не разглядеть.
- **Копируешь функцию и меняешь два слова — остановись, выноси общее.** Прецеденты: `handleFilletApply`/`handleChamferApply` (теперь общий `runEdgeCommand`); в `ViewportContainer` — зеркальные `selectBodyAsTarget`/`selectBodyAsTool`, `setBodyColor`/`resetBodyColor` и три параллельные подсистемы выделения (body/face/edge) с почти одинаковыми set/clear-парами — при следующей правке выделения объединяй, а не добавляй четвёртую копию.
- **Состояние сбрасывает только его владелец.** Мутируй состояние домена через методы его composable/сервиса, а не по чужим refs напрямую: контекст выдавливания сбрасывали четыре разных места, и они разошлись; теперь сброс — только `clearSketchContext`.
- **Мёртвое удаляй в том же изменении.** Неиспользуемые CSS-классы, импорты, переменные, обработчики и декоративные кнопки не переносятся при рефакторинге и не остаются «на потом» (в старом EditorView скопились `shareBtn`, `pillGreen`, `dirtyHint`, `edgesBtn`, `playSep` и мёртвая кнопка «◰»).

## Backend

### Структура слоёв

- **Роуты (`api/routes/`)** — тонкие: парсинг запроса, вызов сервиса, маппинг доменных ошибок в `HTTPException`. Без бизнес-логики и прямых запросов к БД.
- **Сервисы (`services/`)** — вся бизнес-логика. Принимают `AsyncSession`/`Redis`, бросают доменные исключения (`AuthError`, `ProjectError`).
- **Модели (`models/`)** — SQLAlchemy 2.0 mapped-классы. ID — `uuid4().hex` (32 символа). Используй каскады (`ondelete="CASCADE"`) для зависимых сущностей.
- **Схемы (`schemas/`)** — Pydantic. Разделяй `*Request`/`*Create`/`*Update`/`*Response`. На response-моделях — `model_config = {"from_attributes": True}`.

### Асинхронность

- Всё async сверху донизу. Никаких блокирующих вызовов в обработчиках запросов.
- Доступ к БД только через `Depends(get_db)`; Redis — через `Depends(get_redis)`.
- Геометрию backend не считает: она строится в браузерном Worker, сервер только проверяет и сохраняет результат.

### Безопасность (критично)

- **Access token** — JWT, 15 минут, только в заголовке `Authorization: Bearer`.
- **Refresh token** — opaque, 30 дней, только в httpOnly + Secure + SameSite cookie. В БД хранится SHA-256 хэш, не сырой токен.
- **Ротация + family tracking** в Redis: при refresh старый токен помечается `replaced`, новый — `active`; повторное использование `replaced` токена (replay) инвалидирует всю семью. Не упрощай эту логику.
- **Пароли** — bcrypt cost 12. Никогда не логируй пароли/токены/секреты.
- **Rate limiting** входа/регистрации/refresh — Redis-счётчики в `core/rate_limit.py` (по IP и по email). IP клиента берётся из `X-Forwarded-For`/`X-Real-IP` только от доверенных прокси (`TRUSTED_PROXIES`).
- Refresh token никогда не отдаётся в JSON и не принимается из тела запроса — только httpOnly cookie.
- **Изоляция:** каждый запрос к ресурсу проверяет владельца. Не возвращай 404 vs 403 так, чтобы это раскрывало существование чужих ресурсов (сейчас — `404 Project not found`).

### Миграции

- Менял модель — создай миграцию: `make migrate-create name="..."`, проверь сгенерированный diff (autogenerate не всегда точен с типами/индексами).
- Миграции версионируются и применяются через `alembic upgrade head` (`make migrate`). Не правь уже применённые миграции — добавляй новые.

## Frontend

### Состояние

- Глобальное состояние — обычный composable, обёрнутый в `createSharedComposable` (VueUse), в `composables/shared/`. **Не вводи Pinia/Vuex.**
- Локальное состояние компонента — обычные `ref`/`reactive`/`computed`.
- Не клади токены в localStorage. Access token живёт в памяти (`useAuth`), refresh — в httpOnly cookie, недоступной JS.

### API-клиент

- Все запросы — через `useApi()`. Он сам подставляет `Authorization`, шлёт cookie (`credentials: "include"`) и прозрачно обновляет токен по 401 (single-flight через общий promise — не дублируй refresh).
- Ошибки приходят в формате `{ error, error_description }` — обрабатывай их, а не сырой статус.

### UI и дизайн-система

- Компоненты дизайн-системы — префикс `Kr` (`KrButton`, `KrDialog`, …), в `components/ui/`.
- **Общие UI-примитивы развиваем в `@krometra/ui-kit`** (отдельный npm-пакет). Если для задачи не хватает компонента, варианта или доступного поведения, его добавляют в кит и выпускают новую версию пакета. В Крометре затем обнови зависимость и используй `K*` напрямую либо через тонкий совместимый `Kr*`-адаптер. Не создавай вторую локальную реализацию общего контрола только потому, что в текущей версии кита его нет.
- **Сырые `<button>` и `<input>` вне `components/ui/` запрещены** — используй `KrButton`, `KrInput`, `KrNumberInput` и т.д. Если готового Cs-компонента не хватает (нет нужного варианта/размера) — расширь его, а не верстай контрол на месте: в коде уже накопилось ~80 сырых контролов мимо системы, и это разнобой стилей, дублирование CSS и потеря доступности.
- Интерактивные компоненты (диалоги, меню, селекты, дерево, табы, сплиттеры) строй на **zag.js** (headless state machines) + **CSS Modules**. Доступность (WAI-ARIA) идёт из zag — не изобретай заново.
- **Никаких кнопок без обработчика.** Нереализованная фича в UI — это либо `disabled` с hint «В разработке», либо её нет вовсе. Кликабельные муляжи (кнопка есть, клик молчит) уже накапливались — они подрывают доверие к интерфейсу. Тексты UI — на русском.
- Стили — только через токены `--kr-*` (цвета, отступы, радиусы, шрифты). Никакого Tailwind, никаких inline-цветов.
- Темизация — через CSS-переменные.

### Редактор (EditorView)

- **EditorView — только оркестратор.** Карта структуры и правила добавления фич — `web/src/components/editor/README.md`. Ориентир: файл не растёт (~580 строк). Если твой change добавляет в него больше пары десятков строк — логика едет не в тот файл: ей место в `composables/editor/` (состояние/обработчики) и `components/editor/` (разметка).
- **Один домен — один composable.** Состояние и обработчики фичи живут в её composable; сброс и мутации — только через его методы, не по чужим refs (см. «Качество кода»).
- **Меши сцены — только через `useBodyMeshes`** (`trackMesh`/`untrackMesh`/`replaceMesh`/`hydrateBodyMeshes`). Раньше цепочка `removeMesh → addMesh → filter → push` была скопирована в шести местах и расходилась — это источник багов «результат не виден до перезагрузки».
- **Канал управления `window.cadControl`** (e2e-драйвер и MCP-сервер) — часть редактора, а не тестовая надстройка: `useEditorControl` публикует его и в прод-сборке. Операция канала вызывает те же методы composables, что панель и лента. Добавил режим или операцию редактора — добавь операцию канала и имя режима (`web/src/lib/control/README.md`), иначе автоматизация их не увидит.
- Остальные анти-паттерны той декомпозиции (совмещённые обработчики, копипаста, мёртвый код) — общепроектные, вынесены в секцию «Качество кода».

### 3D Viewport

- Three.js используется напрямую через template ref, без TresJS, чтобы контролировать render loop.
- Обязательно освобождай ресурсы в `onUnmounted`: `cancelAnimationFrame`, `renderer.dispose()`, `controls.dispose()`, отключение `ResizeObserver`. Утечки GPU-памяти в CAD критичны.
- Геометрию считает только worker браузерного ядра; вьюпорт отображает его тесселяцию и не дублирует B-rep-вычисления.
- **Сцена обновляется через состояние документа, не точечными мутациями.** Операция меняет `useDocument` — сцена перестраивается из него. Не добавляй/не убирай меши напрямую из обработчиков команд: так трижды рождался баг «результат операции не виден до перезагрузки страницы» (невидимые тела, невидимый вырез).
- **Приёмка любой мутирующей операции:** её результат появляется/исчезает в вьюпорте сразу, без перезагрузки страницы. Проверяй это руками или e2e-спекой до отметки задачи выполненной.

### Типобезопасность

- `npm run build` (включает `vue-tsc --noEmit`) и `npm run lint` должны проходить до коммита.
- **Не добавляй новых ESLint warnings** (обычно это забытые unused imports/vars после рефакторинга) — убирай их в том же изменении. Цель — 0 warnings и гейт в CI.
- Типы API держи в `src/types/` синхронными с Pydantic-схемами backend.

### Прод отличается от дев (проверяй перед фичей)

Классы багов, уже случавшихся из-за разницы окружений — учитывай при разработке, а не при деплое:

- Инстанс может работать по **http:// (не secure context)**: `crypto.subtle` и прочие secure-only Web API там недоступны — нужен фолбэк (прецедент: `crypto.randomUUID` недоступен без TLS).
- На сервере может стоять старый Docker: держи compose-файлы совместимыми с **version 3.3**, без новых ключей.
- `docker compose exec` в ssh-скриптах требует `</dev/null`, иначе съедает stdin скрипта.

## Геометрическое ядро

- Ядро — OCCT/WASM (`replicad`) в Web Worker; чистая логика операций живёт в `web/src/lib/browser*.ts` и покрывается vitest. **Операция без юнит-тестов не считается готовой.**
- **Persistent naming обязателен для каждой новой операции.** Любая операция, меняющая топологию, обязана прокинуть историю модификаций (`Modified()`/`Generated()`) в стабильные имена граней/рёбер. Если этого не сделать, все ссылки (эскиз-на-грани, fillet по рёбрам) молча протухнут при перестроении — этот класс багов уже был.
- Экспорт STEP должен открываться в FreeCAD/Fusion 360 без ошибок — это приёмочный критерий.

## Тестирование

- Backend: pytest, упор на сервисы и контракт `browser-*` загрузок (меш, STEP, версия документа). Обязательны тесты изоляции проектов (чужой пользователь не видит/не меняет проект) и сценариев ротации/replay refresh-токенов.
- Геометрия: vitest на корректность операций ядра (объём, габариты, топология, имена) и round-trip STEP/STL — чистая логика в `lib/browser*.test.ts`, WASM — `workers/geometry/*.test.ts`.
- Не коммить код, ломающий сборку фронта или существующие тесты.
- `backend/pytest.ini` по умолчанию исключает тесты с маркером `integration` (нужен живой backend+DB+MinIO) — их гоняют явно (`pytest -m integration`), обычный `pytest` в CI и локально безопасен без поднятого стека.

### E2E в браузере: два разных режима

- **Интерактивная сессия с GUI**: playwright MCP, подключение через CDP к настоящему видимому Chrome. Требует дисплей — не работает на headless-сервере.
- **Агент без дисплея (сервер, CI)**: используй собственный headless-браузер Playwright, не CDP-attach. Сетап уже есть в `web/`:
  - `npx playwright install --with-deps chromium` — ставит браузер и системные зависимости один раз;
  - `npm run e2e` (или `npx playwright test`) — гоняет спеки из `web/e2e/`.
  - Логин не кликается через форму: `web/e2e/auth.setup.ts` логинится напрямую по API (`/api/auth/register` + `/api/auth/token`) и сохраняет `storageState` (httpOnly refresh-cookie). Дальше SPA сама делает silent-refresh при загрузке (`router/index.ts` → `auth.initialize()`), так что access token в память подхватывается без единого клика по UI.
  - Перед прогоном должен быть поднят стек (`make up`) и фронт: **dev-сервер** (`cd web && npm run dev`, порт 5173) либо production-сборка, адрес которой передаётся в `E2E_BASE_URL`. Спеки редактора идут и по прод-сборке: драйвер ходит в редактор через канал `window.cadControl`, который приложение публикует само. Проверено 12.10.2026 на production-бандле (`vite build`), отданном `vite preview` с прокси `/api`: `soap-dish`, `edge-picking`, `fillet-chamfer-mode`, `z-up-scene`, `control-channel`, `control-features` — 11 тестов зелёные; на nginx-контейнере `web` прогон не делался. Раньше драйвер собирал `window.__cad` обходом `#app.__vue_app__._instance`, а в production-бандле Vue не заполняет `_instance` — отсюда старый запрет. Порт 5173 бывает занят другим проектом — проверь, что по адресу отвечает именно Крометра (`curl localhost:5173/api/health` должен вернуть `"app":"Крометра"`), иначе подними Vite на свободном порту и передай `E2E_BASE_URL`.
  - **Не переиспользуй storageState-куку в спеке, которая делает свои API-вызовы.** Refresh-токены ротируются с family-tracking: две параллельные спеки с одной кукой из `auth.setup` ловят replay-защиту, и backend убивает обе сессии (редирект на логин). Спеке со своим API-контекстом нужен собственный логин через `page.request.post("/api/auth/token", …)` — общий cookie jar с браузером сделает остальное (образец — `web/e2e/editor.spec.ts`).
  - API-роуты требуют завершающий слэш (`/api/projects/`, не `/api/projects`) — иначе FastAPI отвечает 307 с absolute-редиректом на `localhost:8000` мимо vite-прокси.
  - `Playwright Test did not expect test.use() to be called here` сразу во всех спеках после правки `e2e/helpers/cad.ts` — это протухший кэш трансформации, а не ошибка в коде: `rm -rf web/node_modules/.cache/playwright`.

### Драйвер редактора в e2e (`web/e2e/helpers/cad.ts`)

Сквозной сценарий моделирования — `web/e2e/soap-dish.spec.ts`. Всё нетривиальное вынесено в хелпер `CadEditor`; если пишешь новую спеку по редактору, бери его, а не изобретай заново.

Прислали ссылку на живой проект (`/editor/<id>`) с просьбой воспроизвести баг — это скилл `e2e-from-project`: он достаёт историю операций из БД и печатает черновик спеки, руками остаётся выбор рёбер по геометрии и финальные проверки.

Выясненное на живом прогоне 16.08.2026:

- **`locator.click()` виснет на кнопках редактора** — Playwright ждёт «стабильности» элемента, а сцена перерисовывается каждый кадр. Кликай через `dispatchEvent`.
- **После «ОК» в эскизе нельзя сразу жать «Выдавить»**: `startExtrudeFromRibbon` выходит по `if (sketch.sketchMode.value) return`, а сохранение эскиза с сотней линий построения занимает секунды. Дождись размонтирования скетчера.
- **Порог клика по ребру — 14 экранных пикселей** (`composables/viewport/edgePicking.ts`), среди попавших выигрывает ближайшее к курсору на экране. Промах всё равно лечится приближением камеры: соседние рёбра на кромке кармана проецируются в те же пиксели. Повторный клик по ребру снимает выбор — этим хелпер откатывает промахи.
- **`window.cadControl`** — канал управления, который редактор публикует сам (`composables/editor/useEditorControl.ts`, контракт и список операций — `web/src/lib/control/README.md`). `CadEditor` берёт через него состояние, топологию, проекции точек в координаты клика и выделение: `cad.control(op, params)` бросает на ошибке, `cad.request(op, params)` возвращает ответ как есть. После смены режима ничего переустанавливать не нужно; `cad.install()` только ждёт готовности канала и нужен после `page.reload()`. Не хватает данных — добавь операцию в `composables/editor/control/`, а не лезь во внутренности Vue: в прод-сборке их нет.
- **Мутирующие операции канала** (`sketch.create`, `extrude`, `revolve`, `fillet`, `chamfer`, `boolean`, `thread`, `history.undo`/`redo`) строят модель без кликов и возвращают новую запись истории — образцы `web/e2e/control-channel.spec.ts` и `web/e2e/control-features.spec.ts`. Файл STEP/STL без диалога скачивания отдаёт `export`. Ими удобно готовить деталь для спеки, которая проверяет что-то другое; спеки про сам интерфейс (попадание по ребру, панели, ввод размеров) продолжают кликать.
- **Ждать редактор — через `cad.idle()`**, а не паузой: `state.busy` держится, пока идёт операция, сохранение эскиза или перезагрузка тел в сцену.
- **Геометрию проверяй по мешу** (обход сцены, вершины и рёбра), а не по DOM: статус-бар суммирует грани и рёбра по всем телам, включая скрытые промежуточные, и врёт.
- **Не клади нижнюю грань детали ровно в плоскость XY**: хелпер базовой плоскости компланарен грани, и клик разрешается случайно — в настоящем Chrome чаще выигрывает грань, в headless всегда плоскость. Строй деталь симметрично относительно XY или строй от z>0.
- Запуск только сценария моделирования: `npx playwright test e2e/soap-dish.spec.ts`. Из корня репозитория Playwright подхватывает ещё и vitest-файлы `web/src/**/*.test.ts` — гоняй из `web/`.

## Git и процесс

- Работа идёт в `master`; ветка — только под долгое изменение или по просьбе пользователя.
- **Коммит и push — по явной просьбе пользователя.**
- Сообщения коммитов — по сути изменения (что и зачем), в духе истории репозитория.
- Перед коммитом: миграции созданы, `npm run build` и `npm run lint` зелёные, тесты проходят.
