## ADDED Requirements

### Requirement: Документ создаётся вместе с проектом

Каждый проект SHALL иметь ровно один связанный документ. При создании проекта система MUST создать пустой документ (`components: []`, `timeline: []`, `version: 1`) в той же транзакции. Документ MUST удаляться каскадно при удалении проекта.

#### Scenario: Создание проекта создаёт пустой документ

- **WHEN** пользователь создаёт проект через `POST /api/projects/`
- **THEN** в той же транзакции создаётся документ с `components: []`, `timeline: []`, `version: 1`
- **AND** последующий `GET /api/projects/{id}/document` возвращает этот пустой документ

#### Scenario: Удаление проекта удаляет документ

- **WHEN** пользователь удаляет проект через `DELETE /api/projects/{id}`
- **THEN** связанный документ удаляется каскадно
- **AND** в таблице `documents` не остаётся записей с этим `project_id`

### Requirement: Загрузка документа с изоляцией по владельцу

Система SHALL возвращать документ только владельцу проекта. Запрос документа чужого проекта MUST возвращать `404` (тот же ответ, что и для несуществующего проекта, чтобы не раскрывать существование чужих ресурсов).

#### Scenario: Владелец загружает свой документ

- **WHEN** владелец вызывает `GET /api/projects/{id}/document`
- **THEN** система возвращает `200` с `components`, `timeline`, `version`, `metadata`

#### Scenario: Чужой пользователь не видит документ

- **WHEN** пользователь, не являющийся владельцем, вызывает `GET /api/projects/{id}/document`
- **THEN** система возвращает `404`
- **AND** тело ответа не раскрывает существование проекта

#### Scenario: Неаутентифицированный запрос отклоняется

- **WHEN** запрос к `GET /api/projects/{id}/document` приходит без валидного access-токена
- **THEN** система возвращает `401`

### Requirement: Сохранение документа с optimistic locking

Система SHALL сохранять документ только если переданный клиентом `version` совпадает с текущим `version` в БД. При совпадении система MUST записать новое содержимое и инкрементировать `version`. При несовпадении (конкурентное изменение) система MUST вернуть `409` и не изменять данные.

#### Scenario: Успешное сохранение инкрементирует версию

- **WHEN** владелец вызывает `PUT /api/projects/{id}/document` с `version`, равным текущему в БД
- **THEN** система сохраняет `components`/`timeline`/`metadata`
- **AND** возвращает документ с `version`, увеличенным на 1

#### Scenario: Конфликт версий отклоняется

- **WHEN** владелец вызывает `PUT /api/projects/{id}/document` с `version`, меньшим текущего в БД
- **THEN** система возвращает `409`
- **AND** содержимое документа в БД остаётся неизменным
- **AND** ответ содержит `error` и `error_description` о конфликте версий

#### Scenario: Сохранение в чужой проект отклоняется

- **WHEN** не-владелец вызывает `PUT /api/projects/{id}/document`
- **THEN** система возвращает `404`
- **AND** документ не изменяется

### Requirement: Документ — тонкий JSONB-конверт

Документ SHALL хранить `components` и `timeline` как непрозрачные JSON-массивы и `metadata` как JSON-объект, без жёсткой серверной схемы вложенных сущностей (Component/Body/Sketch/Feature). Сервер MUST принимать и возвращать их как есть, не валидируя внутреннюю структуру за пределами того, что это валидный JSON ожидаемого верхнего типа.

#### Scenario: Сервер сохраняет произвольную структуру компонентов

- **WHEN** клиент сохраняет документ с непустыми `components`/`timeline` произвольной вложенной формы
- **THEN** система сохраняет их без потерь
- **AND** последующая загрузка возвращает идентичную структуру

### Requirement: Авто-сейв документа по таймеру

Клиент SHALL отслеживать «грязное» состояние документа (`isDirty`) и автоматически сохранять его не чаще одного раза в 30 секунд при наличии несохранённых изменений. После успешного сохранения состояние MUST становиться «чистым», а локальный `version` — обновляться значением с сервера.

#### Scenario: Грязный документ авто-сохраняется по таймеру

- **WHEN** документ помечен `isDirty` и проходит интервал авто-сейва (30с)
- **THEN** клиент отправляет `PUT /api/projects/{id}/document` с текущим `version`
- **AND** при успехе сбрасывает `isDirty` и обновляет локальный `version`

#### Scenario: Чистый документ не сохраняется

- **WHEN** наступает интервал авто-сейва, но документ не помечен `isDirty`
- **THEN** клиент не отправляет запрос на сохранение

#### Scenario: Конфликт версий при авто-сейве сигнализируется

- **WHEN** авто-сейв получает `409` от сервера
- **THEN** клиент не сбрасывает `isDirty` молча
- **AND** конфликт делается доступным состоянию для отображения пользователю
