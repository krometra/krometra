## ADDED Requirements

### Requirement: Контракт транспорта тесселированного меша

Сервер SHALL отдавать геометрию тела в виде тесселированного меша по контракту: `vertices` (плоский массив float, по 3 на точку), `indices` (плоский массив int — треугольники), `brepTopo` с массивами `faces` и `edges` (идентификаторы топологических элементов для будущей селекции), и `bbox` (мин/макс ограничивающего параллелепипеда). Формат MUST быть стабильным и не зависеть от способа генерации меша.

#### Scenario: Меш отдаётся в полном контракте

- **WHEN** клиент вызывает `GET /api/projects/{id}/geometry/{body_id}/mesh`
- **THEN** ответ содержит `vertices`, `indices`, `brepTopo.faces`, `brepTopo.edges`, `bbox`
- **AND** длина `vertices` кратна 3, длина `indices` кратна 3

### Requirement: Stub-движок геометрии за интерфейсом tessellate

Система SHALL инкапсулировать генерацию меша за интерфейсом `GeometryEngine.tessellate()`. В рамках этого среза реализация MUST быть заглушкой, возвращающей корректный меш единичного куба в полном контракте. Замена заглушки на реальное ядро (OpenCASCADE) MUST не требовать изменения сигнатуры интерфейса, эндпоинта меша или формата ответа.

#### Scenario: Заглушка возвращает валидный куб

- **WHEN** запрашивается меш любого `body_id` существующего проекта
- **THEN** `tessellate()` возвращает меш куба с непустыми `vertices`/`indices`
- **AND** `bbox` соответствует границам куба
- **AND** `brepTopo.faces` содержит идентификаторы 6 граней

### Requirement: Хранение и кэш меш-блобов в MinIO

Сгенерированный меш SHALL сохраняться в объектном хранилище (MinIO) по пути `{projectId}/geometry/{bodyId}.mesh`. При запросе меша система MUST сначала проверять кэш в хранилище и возвращать сохранённый блоб, генерируя его через движок только при отсутствии. Bucket MUST инициализироваться при старте, если он ещё не существует.

#### Scenario: Первый запрос генерирует и кэширует

- **WHEN** меш для `{projectId}/{bodyId}` запрашивается впервые и в хранилище его нет
- **THEN** система генерирует меш через `tessellate()`
- **AND** сохраняет блоб по пути `{projectId}/geometry/{bodyId}.mesh`
- **AND** возвращает меш клиенту

#### Scenario: Повторный запрос отдаётся из кэша

- **WHEN** меш для того же `{projectId}/{bodyId}` запрашивается повторно
- **THEN** система возвращает блоб из хранилища
- **AND** не вызывает генерацию заново

#### Scenario: Доступ к мешу изолирован по владельцу

- **WHEN** не-владелец запрашивает `GET /api/projects/{id}/geometry/{body_id}/mesh`
- **THEN** система возвращает `404`

### Requirement: Отображение меша в 3D-viewport

Клиентский viewport SHALL строить `THREE.BufferGeometry` из `vertices`/`indices` полученного меша и добавлять результирующий меш в сцену. При размонтировании viewport MUST освобождать ресурсы геометрий и материалов добавленных мешей (`dispose`), чтобы не допускать утечек GPU-памяти.

#### Scenario: Меш с сервера отображается в сцене

- **WHEN** `EditorView` загружает документ и запрашивает меш тела
- **THEN** viewport строит `BufferGeometry` из `vertices`/`indices`
- **AND** добавляет меш в сцену поверх сетки/начала координат

#### Scenario: Ресурсы освобождаются при размонтировании

- **WHEN** `EditorView`/viewport размонтируется
- **THEN** геометрии и материалы добавленных мешей освобождаются через `dispose`
- **AND** цикл рендеринга и наблюдатели останавливаются
